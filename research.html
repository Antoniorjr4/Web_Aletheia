The official protocol

AgentDojo v1.2.2, banking suite, official tools and evaluators, the important_instructions attack and a paired baseline vs Λletheia pipeline. The agent is a Λletheia program (banking.ath) connected through a BasePipelineElement.

Coverage and limitations

All 144 attack pairs of one suite, with one model, one attack and one repetition per pair. In a recorded case the model obeyed the injection and proposed a transfer to the attacker's IBAN; the policy refused it and only the legitimate part ran. The historical v0.9 batch (19/144) is superseded but kept in the repository. Zero successes do not imply zero risk.

What this shows

Against prompt injection, Λletheia is as safe as a carefully hardened Python agent — not safer. Where it differs is in what is checked before running, and in cycle 1 the v3 pipeline completed significantly more legitimate tasks under attack with the same security.

What this does not show

v3 and the hardened Python differ in more than one factor (value type, system message, schema order), so the advantage is not attributable to integer cents alone. One suite, one model, one attack. The claim that the language makes development cheaper was refuted in this measurement and is published as such.

What changed after M10

Common syntax accepted (// comments, _ and { .. } in patterns, optional commas); len on text; budget as an ordinary name; several syntax errors per compilation; inventory passed through let; sum x in xs => n, a bounded sum with its range proved by the type. While typing the sum, four pre-existing confidentiality leaks (D14) were found and closed.

Why it is published

A site that shows only the good numbers is the first to be refuted. Today, when a model writes the agent on its own, Python still wins. New evidence requires new, versioned specifications; the frozen M10 guide was not changed and no new paid campaign was run.

The axiom audit

Audited dependencies: propext, Quot.sound and Classical.choice. Three backends — compiled Lean, ARX in Rust and Python — produce the same hash-chained journal, byte for byte, in the differential tests.

What is not yet proved

A complete Lean-to-Rust/Python refinement is not established; the link to the executable is by matching statements and by tests. Several RC modules (for example Confidentiality.lean) model the decision and the propagation, not the whole evaluator. Type soundness does not make a business policy adequate.

From proof to agent

RC1 showed one program surviving real crashes. RC2–RC4 made authority durable and time-aware; RC5–RC6 put the whole agent in the language and ran it against an independent API under automatic supervision; RC7–RC9 added partial execution, exact reports and MCP; RC10 closed the output-channel leg of the toxic flow. Earlier programs keep their Codex roots: a program without confidentiality labels is exactly what it was.

Limits of the candidates

The RC branches and the cycle 1 branch are not merged into main, which still holds the historical v0.9 baseline. Provider behavior, fsync durability and one writer per WAL remain assumptions. Nothing here is certified for production. A decision on the project is scheduled for 8 Dec 2026, after a checkpoint on 1 Dec.

What changed

Rev7 introduces host-derived inventory and telemetry, and contextual scaling constraints. The Python baseline also received operational context, so changes are not attributable solely to the Λletheia compiler.

What did not happen

In the live scenario 05, the model chose Restart rather than an unsafe Scale. Policy rejection of Scale(api,64) was verified in the scripted test, not exercised by that live decision. N=3 is exploratory.
